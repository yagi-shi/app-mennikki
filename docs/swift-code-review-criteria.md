# Swift コードレビュー基準

このドキュメントは、Claude Codeを使用したSwiftコードレビューにおいて、**必須で確認すべき項目のみ**を定義します。
可読性や保守性の細かい改善提案は除外し、リリースブロッカーとなる問題のみを対象とします。

---

## 🎯 レビューの方針

以下の3つの観点**のみ**をチェックします：

1. **Swift文法として問題ないか**（コンパイル・実行時エラーのリスク）
2. **セキュリティリスクがないか**（訴訟・情報漏洩のリスク）
3. **ストアリリース基準を満たしているか**（Apple審査のリスク）

**レビュー対象外：**
- コードスタイル（インデント、命名規則など）
- パフォーマンス最適化（致命的でない限り）
- アーキテクチャの改善提案
- テストコードの追加提案
- リファクタリング提案

---

## 1️⃣ Swift文法チェック

### ✅ 必須確認項目

- [ ] **強制アンラップ（`!`）の誤用**
  - クラッシュリスクがある`!`の使用（特にオプショナルチェーン以外）
  - IBOutlet以外での強制アンラップ
  
- [ ] **メモリリーク**
  - クロージャ内での`self`の強参照（`[weak self]`または`[unowned self]`の欠如）
  - Delegate/Notificationの解放漏れ
  
- [ ] **スレッドセーフティ**
  - UI更新をメインスレッド以外で実行
  - データ競合が発生しうる共有リソースへのアクセス
  
- [ ] **実行時エラーのリスク**
  - 配列の範囲外アクセスの可能性
  - 強制キャスト（`as!`）の不適切な使用
  - ゼロ除算の可能性

### ❌ レビュー対象外

- オプショナルバインディングの書き方（`if let` vs `guard let`）
- アクセス修飾子の最適化（動作に影響しない場合）
- 非推奨APIの使用（代替が明確で動作する場合）

---

## 2️⃣ セキュリティチェック

### ✅ 必須確認項目

- [ ] **個人情報の取り扱い**
  - ユーザーデータの暗号化なしでの保存（UserDefaults、ファイルシステム等）
  - 個人情報のログ出力（`print()`文等）
  - 生体認証データの不適切な取り扱い
  
- [ ] **通信セキュリティ**
  - HTTPSではなくHTTPでの通信（ATS違反）
  - 証明書検証の無効化
  - APIキー・トークンのハードコード
  
- [ ] **データ漏洩リスク**
  - クリップボードへの機密情報コピー
  - スクリーンショットに機密情報が含まれる可能性
  - バックグラウンド時のスクリーンキャプチャ対策なし
  
- [ ] **認証・認可**
  - トークンの安全でない保存（KeyChain未使用）
  - セッション管理の欠如
  - 権限チェックの不備

### ❌ レビュー対象外

- コードの難読化（リバースエンジニアリング対策）
- ログレベルの最適化（機密情報が含まれていない場合）

---

## 3️⃣ ストアリリース基準チェック

### ✅ 必須確認項目

- [ ] **プライバシー関連**
  - 位置情報・カメラ・マイク等の権限リクエストに説明文がない
  - ATT（App Tracking Transparency）の実装漏れ（トラッキングする場合）
  - プライバシーマニフェストが必要なAPIの使用
  
- [ ] **App Store Review Guidelines違反**
  - 未成年向けアプリでの広告ID使用
  - ギャンブル・アダルトコンテンツの不適切な実装
  - アプリ内購入のガイドライン違反（価格表示等）
  
- [ ] **UIデザイン要件**
  - Safe Areaの無視によるノッチ領域への侵入
  - Dynamic Typeへの未対応（アクセシビリティ）
  - ダークモード対応の欠如（色のハードコード）
  
- [ ] **パフォーマンス**
  - メインスレッドでの重い処理（フリーズの原因）
  - 大量のメモリ消費によるクラッシュリスク

### ❌ レビュー対象外

- デザインの美しさ
- アニメーションの滑らかさ（動作する場合）
- ローカライゼーションの完全性（最低限英語対応があれば可）

---

## 📋 レビュー実施方法

### レビュー時の指示例

```
以下のSwiftコードを、`swift-code-review-criteria.md`に記載された基準のみでレビューしてください。

条件：
- 3つの観点（文法・セキュリティ・ストアリリース）のみチェック
- 可読性や保守性の改善提案は不要
- リリースブロッカーとなる問題のみ報告
- 各問題に優先度（Critical/High/Medium）を付与
```

---

## 🔍 レビュー結果の例

### ✅ 良い例

```markdown
## レビュー結果

### Critical Issues
- Line 45: 強制アンラップによるクラッシュリスク
  - `let user = users[indexPath.row]!` → 配列範囲外の可能性

### High Issues  
- Line 78: HTTPSではなくHTTPでの通信（ATS違反）
  - `http://api.example.com` → `https://api.example.com`

問題なし：Medium以下の問題は検出されませんでした。
```

### ❌ 悪い例（このような指摘は不要）

```markdown
## レビュー結果

- 変数名が不明瞭（`a` → `accountBalance`）
- メソッドが長すぎる（100行 → 50行以下に分割推奨）
- コメントが不足している
```

## 📌 補足

### カスタマイズ方法

プロジェクト固有の要件がある場合、以下のセクションを追加できます：

```markdown
## 4️⃣ プロジェクト固有チェック

### ✅ 必須確認項目

- [ ] **社内ライブラリの使用規約**
  - 禁止されているライブラリの使用
  
- [ ] **コンプライアンス**
  - GDPR対応コードの実装漏れ
```

### 定期的な見直し

- Appleのガイドライン更新時
- Swift言語仕様の変更時
- セキュリティ脆弱性の発見時
