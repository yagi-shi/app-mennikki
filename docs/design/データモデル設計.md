## 1. Core Data Entity

### Record（記録）

ラーメンの食事記録を保存するエンティティ。

| フィールド | 型 | 必須 | デフォルト値 | 備考 |
|---|---|---|---|---|
| id | UUID | ✓ | 自動生成 | レコードの一意識別子 |
| storeName | String | ✓ | - | 店舗名（自由入力） |
| ramenType | String | ✓ | - | ラーメンの種類（Enumから文字列で保存） |
| visitDate | Date | ✓ | - | 訪問日 |
| cost | Int16 | - | 0 | 費用（円）、0は未入力扱い |
| rating | Int16 | - | 0 | 星評価（0〜5）、0は未評価 |
| comment | String | - | - | コメント（自由入力） |
| photo | Binary Data | - | - | ラーメンの写真データ |
| isFavorite | Bool | ✓ | false | お気に入りフラグ |
| createdAt | Date | ✓ | 自動設定 | 作成日時 |

## 2. RamenType Enum

ラーメンの種類を定義するEnum。String rawValueで管理し、Core DataにはrawValueを保存する。

```swift
enum RamenType: String, CaseIterable {
    case shoyu = "醤油ラーメン"
    case miso = "味噌ラーメン"
    case shio = "塩ラーメン"
    case tonkotsu = "豚骨ラーメン"
    case tantan = "担々ラーメン"
    case jiro = "二郎系ラーメン"
    case tsukemen = "つけ麺"
    case cold = "冷ラーメン"
    case taiwan = "台湾ラーメン"
    case other = "その他"
}
```

### 使用方法

```swift
// Core Dataへの保存
record.ramenType = RamenType.shoyu.rawValue

// Core Dataからの読み込み
if let ramenType = RamenType(rawValue: record.ramenType) {
    // ramenTypeを使用
}
```

## 3. データの検証ルール

### 必須項目
- 店舗名（storeName）: 空文字列不可
- ラーメンの種類（ramenType）: RamenType Enumのいずれか
- 訪問日（visitDate）: 有効な日付

### オプション項目
- 費用（cost）: 0の場合は未入力扱い、負の値は不可
- 評価（rating）: 0〜5の範囲、0は未評価
- コメント（comment）: 任意の文字列
- 写真（photo）: 任意のバイナリデータ

---

## 4. 画像データの管理

### リサイズ
- 保存前に適切なサイズにリサイズ（推奨: 最大幅1024px）
- アスペクト比を維持
- JPEG圧縮品質: 0.8

### キャッシュ
- メモリキャッシュ: 直近10枚程度
- ディスクキャッシュ: Core Dataに保存

## 5. Core Data設定

### NSPersistentContainer設定

```swift
lazy var persistentContainer: NSPersistentContainer = {
    let container = NSPersistentContainer(name: "mennikki")
    container.loadPersistentStores { description, error in
        if let error = error {
            fatalError("Unable to load persistent stores: \(error)")
        }
    }
    return container
}()
```

### Context管理
- **Main Context**: UI更新用（viewContext）
- **Background Context**: データ保存・更新用（newBackgroundContext()）

## 7. データマイグレーション

### 方針
- Lightweight Migration を優先
- 互換性のない変更の場合はManual Migrationを実装

### 注意事項
- データモデル変更時は新しいバージョンを作成
- マイグレーションポリシーを定義
- ユーザーデータの保護を最優先
